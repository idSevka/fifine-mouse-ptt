# fifine-mouse-ptt

Push-to-talk / push-to-mute для USB-микрофона с боковой кнопки мыши — и
синхронизация со собственной кнопкой микрофона.

Написано и проверено на Fifine USB Microphone под Arch + Hyprland (Omarchy),
но подход применим к любому устройству, у которого есть читаемое evdev-событие.

---

## Зачем это, если «просто бинд» не работает

Обычный путь — повесить бинд `mouse:276` в конфиге оконного менеджера на
press и на release, а логику положить в скрипт с файлом состояния в `/tmp`.
Этот путь ломается, и вот почему:

**1. Hyprland шлёт повторные press при удержании кнопки.** Интервалы плавают —
на одном ресивере замерены 0.2, 0.4, 0.6 и **1.8** секунды между повторами.
Скрипт с защитой по времени («повтор, если прошло меньше N мс») не может
подобрать N: любой фиксированный порог одновременно слишком мал для медленных
повторов и слишком велик для быстрого двойного клика. Повтор, пришедший позже
окна, обрабатывается как новое нажатие, перезаписывает запомненное состояние —
и при отпускании микрофон возвращается **не туда**, где был. Симптом, который
видит пользователь: «правильно работает только в одном положении».

**2. У микрофона может быть два независимых гейта мьюта.** У Fifine именно так:
внутри чипа есть аппаратный гейт со светодиодом (управляется сенсорной кнопкой
на корпусе), а `Mic Capture Switch` в ALSA/PipeWire — отдельный, и его-то и
видят приложения. Светодиод отражает **оба**, система — **только второй**.
Сенсорная кнопка при этом не транслирует своё состояние в систему вообще.

Как решает этот проект:

- **Читаем evdev напрямую**, а не через биндинг. Одно физическое нажатие —
  ровно одно `value=1` и одно `value=0`.
- **Состояние держим в памяти процесса**, а не в файле. Его невозможно
  затереть лишним событием.
- **Защита — булев флаг, а не таймер.** Пока кнопка логически зажата, любой
  повторный `value=1` игнорируется. Автоповтор ядра (`value=2`) пропускается.
- **Слушаем и сенсорную кнопку микрофона** (evdev `code 256`) и переключаем
  программный мьют вслед за ней, чтобы состояние в системе и на светодиоде
  совпадали.

## Установка

```bash
git clone https://github.com/<ваш-логин>/fifine-mouse-ptt.git
cd fifine-mouse-ptt
./install.sh
```

`install.sh` копирует скрипты в `~/.local/bin`, создаёт автозапуск в
`~/.config/autostart` и проверяет, что демон находит устройства.

Если у вас другое железо — сначала посмотрите, что найдено:

```bash
fifine-ptt --status
```

```
alsa_input.usb-fifine_...analog-stereo: unmuted
мышь:      ['/dev/input/event3']
сенсорная: ['/dev/input/event7']  (обработка: ВКЛ)
```

Если пути пустые — задайте свои маски через переменные окружения (см. ниже).

## Как это работает

```
     боковая кнопка мыши                    сенсорная кнопка микрофона
     BTN_EXTRA = 276                        code 256 (event отдельного устройства)
            │                                        │
            ▼                                        ▼
     ┌──────────────────────────────────────────────────────┐
     │  fifine-ptt — демон, читает /dev/input/event*         │
     │                                                       │
     │  нажатие:  прочитать pactl → запомнить → инвертировать│
     │  отпуск:   вернуть запомненное                        │
     │  сенсор:   прочитать pactl → инвертировать            │
     └──────────────────────────────────────────────────────┘
                              │
                              ▼
                        pactl set-source-mute
                              │
                              ▼
                    Mic Capture Switch (ALSA / PipeWire)
                              │
                              ▼
                    слышно / не слышно в приложениях
```

Стратегия (push-to-talk или push-to-mute) **выбирается на каждом нажатии** по
фактическому состоянию, прочитанному в этот момент:

```
press: было muted   -> стало unmuted     # микрофон был выключен → включаем
release: вернул muted

press: было unmuted -> стало muted       # микрофон был включён → глушим
release: вернул unmuted
```

## Переменные окружения

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `FIFINE_SOURCE` | имя источника Fifine | какой PulseAudio/PipeWire источник переключать |
| `FIFINE_BTN` | `276` | код кнопки мыши (`BTN_EXTRA`) |
| `FIFINE_DEVICE_MATCH` | `Beken USB Gaming Mouse` | подстрока имени устройства мыши |
| `FIFINE_TOUCH` | выкл | включить синхронизацию с сенсорной кнопкой |
| `FIFINE_TOUCH_BTN` | `256` | код сенсорной кнопки |
| `FIFINE_TOUCH_DEVICE_MATCH` | `fifine` | подстрока имени микрофона |
| `FIFINE_OSD` | выкл | показывать всплывашку при переключении |
| `FIFINE_DEBUG` | выкл | писать переходы состояний в stderr |

По умолчанию `FIFINE_TOUCH` **выключен**: обработка сенсорной кнопки меняет
поведение привычного физического контрола, поэтому включайте осознанно.

## Команды

```bash
fifine-ptt                  # запустить демон (обычно через автозапуск)
fifine-ptt --status         # показать состояние и найденные устройства
fifine-ptt-selftest         # прогнать тесты логики (6 сценариев)
mic-status                  # состояние на двух уровнях: PipeWire и чип ALSA
watch -n0.3 mic-status      # то же, но в реальном времени
```

`mic-status` — главный инструмент диагностики. Он показывает состояние сразу
на двух уровнях и подсвечивает расхождение между ними:

```
16:35:11       PipeWire:    ВКЛЮЧЁН (live)   [no]
               ALSA (чип): ВКЛЮЧЁН (live)   [on]
```

## Диагностика

**Кнопка не срабатывает вообще.** Проверьте, что демон запущен
(`pgrep -af fifine-ptt`) и что он видит устройство (`fifine-ptt --status`).
Затем запустите с `FIFINE_DEBUG=1` и нажмите кнопку — в stderr появятся строки
переходов.

**Кнопка срабатывает через раз или «наоборот».** Почти наверняка рассинхрон
источников состояния: сравните `mic-status` с тем, что показывает индикатор
вашего устройства. Подробнее — в [docs/how-it-works.md](docs/how-it-works.md).

**Устройство не найдено.** Узнайте реальные имена и коды:

```bash
grep -A6 -i "mouse\|microphone" /proc/bus/input/devices
for ev in /sys/class/input/event*; do
  printf '%s %s\n' "$(basename $ev)" "$(cat $ev/device/name 2>/dev/null)"
done
```

Матчинг идёт по подстроке имени **и** по наличию нужного кода в
`capabilities/key`, поэтому путаницы между интерфейсами одного устройства не
возникает.

## Ограничения

- Читать `/dev/input/event*` может только пользователь в группе `input`
  (или root). Проверить: `id -nG | tr ' ' '\n' | grep -x input`.
- Демон переключает `Mic Capture Switch`. Если у вашего микрофона есть
  **аппаратный** гейт, состояние которого ОС не читает, программный и
  аппаратный мьют могут расходиться — именно от этого спасает
  `FIFINE_TOUCH=1`, если кнопка устройства отдаёт evdev-событие.
- Проверено на Fifine USB Microphone + мышь Beken USB Gaming Mouse под
  Hyprland. На другом железе понадобится подставить свои коды.
